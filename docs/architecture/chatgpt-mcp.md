# Подключение CRM 3.0 к ChatGPT через MCP

CRM публикует приватный MCP-сервер по адресу `https://zoom78.com/mcp`.
ChatGPT подключается к нему через экран «Создать MCP-приложение» с OAuth.
Архив плагина и OpenAI API key для этого подключения не требуются.
Доступ к существующим платным AI-функциям CRM использует её текущую конфигурацию Polza.

## Устройство

- Django обслуживает вход, согласие OAuth, выдачу и отзыв токенов, discovery metadata и выдачу файлов.
- Сервис Compose `mcp` использует тот же backend image, PostgreSQL и media volume. Он запускает
  `python -m uvicorn apps.mcp_connector.server:application --host 0.0.0.0 --port 8001 --no-access-log`.
  Порт `8001` не публикуется на хосте. Обычный backend продолжает работать через Gunicorn.
- Для MCP переопределён entrypoint: запуск не повторяет миграции, создание суперпользователя и сборку статики.
- Nginx направляет `/mcp` в MCP-процесс, а `/oauth/`, `/.well-known/oauth-*` и `/mcp-files/` — в Django.
  Эти маршруты доступны только по HTTPS; HTTP-входы на портах 80 и 8000 отвечают `403`.
- Streamable HTTP работает без состояния транспортной сессии. Длительные операции возвращают сохранённое задание.

Конфигурация backend и MCP-процесса должна совпадать:

```dotenv
MCP_PUBLIC_URL=https://zoom78.com/mcp
MCP_OAUTH_ISSUER=https://zoom78.com
MCP_FILE_DOWNLOAD_HOSTS=oaiusercontent.com
```

Значения входят в `.env.production.example`; реальные настройки остаются в серверном `.env.production`.
`MCP_PUBLIC_URL` — точный идентификатор OAuth resource, без завершающего `/`.
Nginx сохраняет исходные Host и схему запроса. Для другого домена нужно согласованно изменить
эти значения, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, сертификат и конфигурацию reverse proxy.
При `DEBUG=False` cookies сессии и CSRF имеют флаг `Secure`: вход в Django admin и OAuth
требует HTTPS. Для локальной отладки входа по HTTP нужен `DEBUG=True`; локальный reverse proxy
при этом продолжает блокировать MCP/OAuth по HTTP.

## Первоначальная настройка

Развёртывание выполняется через существующий CI/CD после согласования доступа к production.
Backend применяет стандартные миграции Django до старта MCP. На этапе проверки изменения
не предоставляют доступ ни одному пользователю автоматически.

После миграций администратор явно разрешает подключение существующей учётной записи:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production exec backend \
  python manage.py grant_mcp_access --username Vova
```

Команда находит пользователя и сохраняет разрешение по его ID. Переименование пользователя
не передаёт доступ другому аккаунту. Позднее таким же способом можно разрешить отдельного сотрудника.
Разрешение и scopes можно просматривать и изменять в Django admin.

Зарегистрируйте OAuth-клиент с точным redirect URI, показанным ChatGPT в настройках MCP-приложения:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production exec backend \
  python manage.py configure_mcp_client \
  --name ChatGPT --redirect-uri 'ТОЧНЫЙ_HTTPS_CALLBACK_ИЗ_CHATGPT'
```

Новый `client_id` и `client_secret` выдаются для ручного ввода в расширенные настройки OAuth ChatGPT.
Не добавляйте их в Git, описание приложения, промпты или общие журналы. При необходимости
перевыпуска используется `--rotate-secret`; повторный показ действующего секрета не предусмотрен.
Callback разрешается точным совпадением, без wildcard. Используется Authorization Code с PKCE S256,
обновлением и отзывом токенов; клиентские пароли не передаются модели.

Discovery endpoints:

- `https://zoom78.com/.well-known/oauth-authorization-server`
- `https://zoom78.com/.well-known/oauth-protected-resource/mcp`
- `https://zoom78.com/.well-known/oauth-protected-resource` — совместимый alias того же resource.

## Подключение в ChatGPT

1. Откройте «Новый плагин» → «Создать MCP-приложение».
2. Назовите подключение, например `CRM 3.0`.
3. Введите URL `https://zoom78.com/mcp`, выберите **OAuth**.
4. Проверьте обнаруженные настройки и внесите client ID/secret в расширенные настройки OAuth.
5. Проверьте предупреждение и создайте подключение. Установите созданный плагин, если интерфейс предлагает это отдельно.
6. Подключите аккаунт: откроется страница CRM. Войдите под `Vova` и подтвердите запрошенные scopes.
7. Выберите CRM через `@` в чате и выполните проверочные запросы ниже.

Названия пунктов могут отличаться между версиями интерфейса ChatGPT. Настройка OAuth и поведение
подтверждений описаны в [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/custom-mcp-server).

## Возможности и права

Каждая операция представлена отдельным инструментом с именем, параметрами и аннотациями.
Произвольных URL, HTTP-методов, SQL и административных операций через MCP нет.
Вызовы выполняются от имени пользователя OAuth с сохранением авторства и канала `ChatGPT`.

| Область | Возможности |
| --- | --- |
| Клиенты и сделки | Поиск, карточки, создание и изменение, история, закрытие, восстановление, дубли и объединение. |
| Работа со сделкой | Задачи, исполнители, сроки, чеклисты, заметки, сообщения и уведомления. |
| Страхование | Полисы, предложения, участники, документы, транспорт, ипотека, заявки и их версии. |
| Финансы | Платежи, финансовые записи, ведомости, статусы, сводки и поддерживаемые экспорты. Это учёт CRM, а не банковские переводы. |
| Файлы | Каталог, текст и страницы, загрузка вложений ChatGPT, скачивание и поддерживаемые операции с файлами. |
| Почта | Адрес и создание ящика сделки, чтение писем и явный запуск импорта. Отправка писем не добавлена. |
| AI | Библиотека, личные чаты, запросы и состояние заданий. Платные операции выполняются отдельной явной командой. |

Scopes `crm.read`, `crm.write`, `crm.destructive`, `crm.files`, `crm.mail`, `crm.ai` ограничивают
разрешённые инструменты, но не заменяют права конкретного пользователя на объекты CRM.
Каждый вызов перепроверяет активность аккаунта, разрешение подключения и действующие права.
Если ChatGPT не указал scopes, экран согласия предлагает разрешённые этому пользователю
возможности. Явно запрошенный более узкий набор сохраняется; ограничение пользователя не расширяется.
Обычные ключи Codex не используются и остаются отдельным каналом интеграции.

Действующие права разделов различаются. В частности, каталог клиентов в CRM общий для вошедших
пользователей: подключение сотрудника не создаёт новую изоляцию клиентов «только по своим сделкам».
Перед включением новых сотрудников проверьте их доступ и связи на тестовых данных.

Через MCP не предоставляются управление пользователями, ролями, паролями, настройками интеграций
и произвольными почтовыми ящиками. Старый MVP оформления Сбера, интерфейс которого удалён,
в реестр инструментов не входит.

## Предпросмотр и повторные запросы

Удаление, объединение, перенос, финансовые изменения, изменение доступа, замена важных реквизитов
и массовые операции требуют предпросмотра. Он показывает точные изменения и зависимости,
не создаёт папки, заметки или внешние задания. Подписанный токен действует 30 минут и связан
с пользователем, OAuth-клиентом, операцией, параметрами и исходным состоянием.

Применение повторно проверяет права и актуальность. Изменённые исходные данные требуют нового
предпросмотра. Записи защищены UUID идемпотентности: точный повтор возвращает сохранённый результат,
а другое тело с тем же UUID отклоняется. Не повторяйте внешний вызов с новым UUID, если его
результат ещё неизвестен; сначала проверьте состояние исходного запроса или задания.

Подтверждение человеком обеспечивает интерфейс ChatGPT. Аннотации инструментов и предпросмотр
не являются отдельным серверным доказательством клика человека. Пользовательские настройки
ChatGPT могут запрашивать подтверждение также для обычных записей.

## Файлы и конфиденциальность

Каталог и чтение содержимого проверяют владельца и принадлежность файла. Чтение не создаёт
папку Drive, заметку или платное AI-задание. Текст и страницы извлекаются существующими
локальными средствами; применяются ограничения размера и объёма ответа.

Загрузка из ChatGPT использует стандартные file params. Получение внешних файлов ограничено
доверенными HTTPS-источниками, проверкой адресов и перенаправлений, таймаутом и пределом размера.
Доверенные домены задаются через `MCP_FILE_DOWNLOAD_HOSTS` (список через запятую); по умолчанию
разрешён `oaiusercontent.com`. Не добавляйте произвольные домены и внутренние адреса для обхода ошибки загрузки.
Оригинал для скачивания выдаётся по краткосрочной ссылке `/mcp-files/<ticket>/`; ссылка является
временным разрешением на конкретный файл и не предназначена для публичного распространения.
При выдаче перепроверяются активность пользователя, разрешение подключения и доступ к файлу.

Для MCP/OAuth/файловых ссылок в Nginx отключён access log, для Uvicorn — access log процесса.
В HTTPS location этих маршрутов также отключён error log: сообщения об ошибке upstream иначе
могут содержать OAuth query или signed ticket в URL. Диагностика доступности выполняется через health и состояние контейнеров.
Не включайте логирование токенов, OAuth query, тела запросов, документов и signed ticket.
Пароли созданных почтовых ящиков и технические секреты не передаются в ответы инструментов.

## Проверка и отзыв доступа

Локальные проверки backend выполняются в его виртуальном окружении:

```powershell
cd backend
.venv\Scripts\python.exe -X utf8 manage.py check --settings=config.test_settings
.venv\Scripts\python.exe -m pytest apps/mcp_connector
.venv\Scripts\python.exe -m black --check .
.venv\Scripts\python.exe -m isort --check-only .
.venv\Scripts\python.exe -m ruff check .
```

Из корня проекта проверяется конфигурация без реальных production-секретов:

```powershell
docker compose -f docker-compose.prod.yml --env-file .env.production.example config --quiet
backend\.venv\Scripts\python.exe -X utf8 -m unittest scripts.test_ci_quality_gate scripts.test_production_compose
```

CI включает тесты MCP в backend core, собирает общий backend image и выполняет внутри него
`scripts/check_mcp_runtime.py`: старт ASGI-процессов, health, discovery и отказ без токена.
Deploy ожидает health MCP и проверяет единый IMAGE_TAG сервисов.
Локальный HTTP prod-like proxy блокирует MCP/OAuth; полный OAuth-тест выполняйте на HTTPS-стенде.

Сквозная приёмка в ChatGPT проводится на тестовых данных:

1. «Используй CRM 3.0: покажи мой профиль и найди тестовую сделку …».
2. «Прочитай документ … из этой сделки и укажи источник и страницы».
3. «Создай задачу … в тестовой сделке»; проверьте автора в CRM.
4. «Подготовь изменение …»; проверьте предпросмотр, подтвердите применение и прочитайте результат.
5. Повторите вызов с тем же UUID и убедитесь в отсутствии дубля.
6. Отзовите доступ и убедитесь, что следующий вызов отклонён.

Отзыв разрешения пользователя:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.production exec backend \
  python manage.py grant_mcp_access --username Vova --revoke
```

Для нового подключения потребуется снова явно разрешить доступ. Отдельный OAuth-токен можно
отозвать через `/oauth/revoke/`; отключение аккаунта CRM также прекращает доступ.
При откате сначала остановите сервис MCP и закройте публичные маршруты; не удаляйте базы и media volumes.
