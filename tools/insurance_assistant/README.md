# Локальный страховой RAG-помощник

Локальный интерфейс для поиска по страховым документам. Документы, векторы и история хранятся в `data/` и не попадают в Git. Для генерации найденные фрагменты отправляются в Codex App Server текущего пользователя.

## Запуск

1. Установите Docker Desktop и войдите в Codex CLI (`codex login`).
2. Скопируйте `.env.example` в `.env` и укажите `POLZA_AI_API_KEY`. Этот файл
   игнорируется Git и нужен для облачных эмбеддингов Polza.ai.
3. В PowerShell из этой папки создайте виртуальное окружение и установите зависимости:

   ```powershell
   python -m venv .venv
   .venv\Scripts\python -m pip install -r requirements.txt
   docker compose -f docker-compose.local.yml up -d
   .venv\Scripts\python -m insurance_assistant
   ```

3. Откройте `http://127.0.0.1:8765`.

На Windows запуск использует `codex.exe` (либо `codex.cmd`), а не PowerShell-обёртку `codex.ps1`; поэтому локальная политика выполнения PowerShell не мешает ответам Codex.

## Публичные документы РЕСО по автострахованию

После запуска помощника можно собрать актуальные публичные правила РЕСО по автострахованию и официальные страницы с инструкциями по урегулированию ОСАГО/КАСКО, затем передать их в локальный RAG:

```powershell
.venv\Scripts\python -X utf8 scripts\collect_reso_auto.py
```

Загрузчик принимает только `reso.ru` и `storage.reso.ru`, пропускает архивные правила и также берёт актуальные документы из общего каталога правил, относящиеся к автомобилям. Для страниц-инструкций он сохраняет только полезный текст без навигации и скриптов. URL, хеш и статус сохраняются в `data/sources/reso_auto/manifest.json`. Для проверки списка PDF без скачивания и эмбеддингов используйте `--discover-only`.

В production сбор запускается внутри контейнера `insurance_assistant`; он использует уже заданную внутреннюю авторизацию только для обращений к своему локальному API и никогда не отправляет служебные заголовки на `reso.ru`. Команда: `docker exec crm3-insurance-assistant python scripts/collect_reso_auto.py`.

Переменные окружения: `INSURANCE_ASSISTANT_DATA_DIR`, `INSURANCE_ASSISTANT_QDRANT_URL`, `INSURANCE_ASSISTANT_HOST`, `INSURANCE_ASSISTANT_PORT`, `INSURANCE_ASSISTANT_CODEX_COMMAND`, `INSURANCE_ASSISTANT_CODEX_MODEL`, `INSURANCE_ASSISTANT_CODEX_MODELS`, `INSURANCE_ASSISTANT_TOP_K`, `INSURANCE_ASSISTANT_RETRIEVAL_CANDIDATES`, `INSURANCE_ASSISTANT_RETRIEVAL_SEMANTIC_WEIGHT`, `INSURANCE_ASSISTANT_RETRIEVAL_LEXICAL_WEIGHT`, `INSURANCE_ASSISTANT_RETRIEVAL_MAX_PER_DOCUMENT`, `IA_EMBEDDING_PROVIDER`, `IA_EMBEDDING_MODEL`, `POLZA_AI_API_KEY`, `POLZA_CHAT_BASE_URL`, `POLZA_CHAT_MODEL`, `IA_EMBEDDING_BATCH_SIZE`. <!-- pragma: allowlist secret --> По умолчанию используется `polza` с `text-embedding-3-large` (3072 измерения); тексты для создания векторов передаются в Polza.ai. Поиск гибридный: Qdrant ищет похожие по смыслу фрагменты, а локальный SQLite FTS5 — точные термины, номера пунктов и фразы; затем результаты объединяются и ограничиваются по числу фрагментов одного документа. В интерфейсе можно вручную выбрать Codex или Polza и модель. Для Polza показывается стоимость, если API возвращает `usage.cost_rub`; для Codex стоимость через App Server не доступна и помечается как `н/д`. Векторы загружаются пакетами по 32, чтобы не превысить лимит Qdrant. Адрес интерфейса по умолчанию — только `127.0.0.1`.

В CRM production используется только Polza: модель хранится в настройках каждого личного чата и применяется к следующему вопросу. Если сохранённая модель исчезла из каталога Polza, система просит выбрать доступную вручную и не подменяет её автоматически.

Чтобы вернуться к полностью локальным эмбеддингам, задайте `IA_EMBEDDING_PROVIDER=local`, модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` и отдельно установите `sentence-transformers`. Это снова потребует PyTorch, который на данной машине блокируется политикой Windows.

## Границы безопасности

Этот этап не подключается к CRM или VPS и не выполняет запись внешних данных. Файлы документов считаются недоверенными данными: инструкции внутри них не передаются как команды. Помощник работает как ассистент страхового агента с продуктами разных компаний, но отвечает только при наличии найденных источников и передаёт их с ответом как цитаты. Он обязан различать страховщика, продукт, риск, версию и период действия документа; условия разных продуктов и страховщиков не смешиваются. Для сравнений помощник указывает компанию и продукт для каждого вывода, а также отмечает подтверждённое, неоднозначное и отсутствующие данные. Он может предложить, что проверить или уточнить, но не обещает выплату, согласование убытка, юридический результат либо другое решение страховщика.

Для типичных бытовых формулировок (например, «без справок») поиск дополнительно учитывает юридические термины правил (например, «без предоставления документов» и п. 11.2.4.1), а модель должна явно отличать прямой текст пункта от пояснения. Если источников или ключевых параметров недостаточно, помощник прямо сообщает об этом и кратко уточняет страховщика, продукт, версию/дату документа, регион, объект, риск или стадию урегулирования.

В CRM библиотека общая для всех сотрудников и может разделяться по веткам `страховщик → вид страхования → продукт`. На вкладке «Библиотека» дерево папок работает как навигация: выбранная ветка фильтрует только список общих документов и не меняет настройки чата. Управление документами находится только на этой вкладке. Модель Polza и область поиска сохраняются отдельно для каждого личного чата и настраиваются в его шапке. При вопросе фильтр области применяется и к семантическому Qdrant-поиску, и к точному FTS5-поиску до объединения результатов. Пустая область означает всю библиотеку. Файлы без полной классификации попадают в «Нераспределено»: они доступны в поиске по всей библиотеке или при явном выборе этой ветки. Перенос файла в другую ветку меняет только его метаданные, без нового создания эмбеддингов. Доступные типы документа: правила, тарифы, инструкция, бланк, образец полиса и прочее.

## API

- `POST /api/documents` (`multipart`, поле `files`), `GET/DELETE /api/documents/{id}`
- `GET /api/documents/{id}/content` — исходный файл для авторизованного CRM-прокси; путь к хранилищу не раскрывается.
- `GET /api/catalog` — дерево веток источников и значения для подсказок при загрузке.
- `PATCH /api/documents/classification` — массовое назначение ветки документам без переиндексации.
- `POST/GET/DELETE /api/conversations`, `PATCH /api/conversations/{id}` для модели и области поиска чата, `GET /api/conversations/{id}/messages`
- `POST /api/conversations/{id}/messages` — SSE: `sources`, `delta`, `error`, `done`
- `GET /api/providers` — доступные провайдеры и каталог моделей Polza.
- `GET /api/usage` — локальная статистика запросов и расходов.
- `GET /health`

Поддерживаются PDF, DOCX, XLSX, PPTX, TXT, MD, CSV, HTML, EML, MSG и изображения. Для сканов требуется установленный в системе Tesseract с языками `rus` и `eng`.
